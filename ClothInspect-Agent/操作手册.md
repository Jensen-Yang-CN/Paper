# ClothInspect-Agent 操作手册

## 零、先回答一个问题：需要"打包"吗？

**不需要。双击 `start.bat` 就能用，现在就可以。**

先纠正一个概念：`start.bat` **不是打包出来的 exe**，它是个"启动器脚本"。
所谓"打包"（PyInstaller 打成单个 exe）是把 Python 解释器和所有依赖塞进一个文件里，
那是为了**发给别人、对方没装 Python 时也能跑**。你自己用不需要。

你以前"每次都用命令行启动"，其实命令行敲的那些，就是 `start.bat` 现在替你做的事：

| 你以前手动敲 | start.bat 自动做 |
|---|---|
| `cd backend` | 用 `$PSScriptRoot` 定位目录 |
| `conda activate xxx` / 指定 python 路径 | 自动搜索 label-studio 环境 |
| 检查依赖装没装 | 自动 `import ultralytics, fastapi` 试一下 |
| `npm run build` | 检测 `dist` 不存在才构建 |
| `python run.py` | 启动服务 |
| 手动开浏览器输网址 | 6 秒后自动打开 |

所以不是"你之前没打包"，是**之前的项目里没人替你写这个脚本**。

### 那什么情况才需要打包？

只有这两种：
* 要发给**没装 Python / Node 的同学或评委**，让他们双击就跑
* 要放到**没网络、没开发环境**的机器上演示

真打包的话，因为带 torch，体积会到 **2~3 GB**，而且要单独处理模型权重路径，
打包一次比现在麻烦得多。**现在这套不需要，建议就先这样。**

## 一、启动

### 用哪个虚拟环境

**`label-studio`** 这个 conda 环境，完整路径：

```
E:\Miniconda\envs\label-studio\python.exe
```

选它的原因：里面已经有 `ultralytics 8.3.217` + `torch 2.1.2+cu118`（能用 GPU），
后端要用的 `fastapi / uvicorn / python-multipart` 也都在。
**不用新建环境，也不用重装 torch。**

### 启动方式

**双击 `start.bat`** 就行。

脚本会自动找到 label-studio 环境、检查权重、构建前端（首次）、启动服务并打开浏览器。

> ⚠️ **启动后那个黑色命令行窗口不要关**。窗口关掉 = 服务停止 = 网页打不开。
> 想停服务就在窗口里按 `Ctrl + C`。

如果自动没找到环境，手动指定：

```powershell
cd E:\CodeBase_YangJunJie\Paper\ClothInspect-Agent
.\start.ps1 -Python "E:\Miniconda\envs\label-studio\python.exe"
```

其他常用参数：

```powershell
.\start.ps1 -Port 8080      # 换端口（8000 被占用时）
.\start.ps1 -NoBrowser      # 不自动开浏览器
.\start.ps1 -Rebuild        # 强制重新构建前端
```

### 启动后

| 地址 | 用途 |
|---|---|
| http://127.0.0.1:8000 | 系统主界面 |
| http://127.0.0.1:8000/docs | 接口文档，可在线调接口 |

**停止服务**：在运行窗口按 `Ctrl + C`。

启动日志里确认这两行就说明一切正常：

```
多模态复核后端: 真实调用 qwen3-vl-plus
YOLOv11 预热完成，推理设备: 0
```

如果第二行显示"离线启发式"，说明 API Key 没读到 —— 检查项目根目录的 `.env`。

## 三、功能怎么操作

### 1. 首页引导

看方法流程和论文核心结果，不用操作。
想了解系统原理就点这里，**第一次用建议先看 30 秒**。

### 2. 检测工作台（主要用这个）

操作顺序：

1. **选图** —— 两种方式任选
   * 把图片拖进虚线框，或点虚线框选文件（JPG/PNG/BMP/WEBP，≤20MB）
   * 点右边内置样例：**每张样例自带真实标注**（写着"破洞×2""污渍×4"），
     拿来对照系统检得对不对最方便
2. **调阈值 T**（不懂就跳过，默认 0.6 就是论文推荐值）
   * `0.50` 低预算 —— 复核调用少，省钱
   * `0.60` 推荐 —— Pareto 膝点，性价比最高
   * `0.70` 高精度 —— 复核翻倍，指标更高
   * 阈值含义：**置信度 ≥ T 的框直接信 YOLO；< T 的框才送给大模型复核**
3. **点"开始检测"** —— 等 2~60 秒（取决于要复核几个框，每次复核约 2.5 秒）
4. **看右侧「Agent 推理轨迹」** —— 每一步做了什么、耗时多少，
   点"查看细节"能展开看参数和大模型的判断理由
5. **看下方结果**
   * 图上框：颜色区分类别，鼠标悬停高亮，点一下定位
   * `逐框明细` 表：每个框的置信度、路由去向、复核结论、**类别纠错标记**
   * `仅 YOLO 与协同结果对比`：同一张图两种模式差在哪
   * `送给多模态大模型的局部视觉证据`：实际送进去的裁剪图 + 大模型结论
6. **切模式对比** —— 图片右上角 `协同结果 / 仅 YOLO 基线` 一键切换，
   能直观看出协同多找了还是少找了
7. **导出报告** —— 生成带框和结论汇总的 PNG，可直接放软著材料

**高级参数**（点开"高级参数"才看得到，一般不用改）：
* `YOLO 推理阈值` 默认 0.25 —— 放宽下限，让更多疑难框有机会被复核
* `仅 YOLO 对照阈值` 默认 0.40 —— 论文诚实基线口径

### 3. 检测记录

* 顶部卡片是累计统计（记录数、缺陷框、大模型调用、平均耗时、类别分布）
* 点任意记录卡片 → **上方就地展开完整结果**（图 + 框 + 全部明细）
* 搜索框按文件名查；每条卡片右下角 `✕` 删除；右上角"清空"删全部

### 4. 实验结果

论文定版数据，分四个标签页看：

| 标签 | 内容 |
|---|---|
| 核心对比 | 四组方法对比表 + 方法框架图 + 数据集与基线 |
| 阈值与成本 | Pareto 曲线、阈值扫描表、H3 成本-性能权衡、H1 置信度-错误率曲线 |
| 消融实验 | 四个消融方案 + H2 局部裁剪 vs 整图的直接证据 |
| 难样本与假设 | 按类别的召回对比、三个假设的验证状态、必须如实说明的边界 |

这里的数字直接读论文定版文件，**和论文里的数字一致，不会漂移**。

### 5. 关于系统

运行环境自检、七个软件功能模块、Agent 工具清单（含 Function Calling 声明）、
技术栈。写软著材料时对着这页抄。

## 四、常见问题

**Q：不想开浏览器/服务，只想验证核心链路能跑？**

```powershell
cd E:\CodeBase_YangJunJie\Paper\ClothInspect-Agent\backend
& "E:\Miniconda\envs\label-studio\python.exe" scripts\smoke_test.py --list-samples
& "E:\Miniconda\envs\label-studio\python.exe" scripts\smoke_test.py --sample v00166.jpg
```

会打印完整路由、复核、融合过程和推理轨迹。

**Q：想验证系统跑的是不是论文那套方法？**（不消耗大模型额度）

```powershell
cd backend
& "E:\Miniconda\envs\label-studio\python.exe" scripts\validate_subset.py --n 300 --no-vlm
```

应输出基线 F1(严格) = 0.5150，与论文 0.515 一致。

**Q：8000 端口被占用？**
换端口：`.\start.ps1 -Port 8080`

**Q：改了前端代码页面没变？**
`dist` 是构建产物，要重新构建：

```powershell
cd frontend
npm run build
```

或者开发模式（带热更新，改完立即生效）：

```powershell
cd frontend ; npm run dev     # 访问 http://localhost:5173
```

**Q：检测接口报 503 / 找不到权重？**
把 `Final_Model_V6_best.pt` 放到 `backend\assets\weights\`，
或在 `.env` 里设 `YOLO_WEIGHTS=<完整路径>`。

**Q：没有 GPU？**
`.env` 里把 `YOLO_DEVICE=0` 改成 `YOLO_DEVICE=cpu`，重启即可（会慢一些）。

**Q：想清空所有数据和记录？**
删掉 `backend\data\` 下的 `clothinspect.db`、`uploads\`、`crops\`、`reports\` 即可，
会自动重新创建。

**Q：备份/搬家？**
整个 `ClothInspect-Agent` 文件夹拷走即可。但注意 `.env` 里有 API Key，
`frontend\node_modules` 和 `backend\data` 可以不用拷（能重建）。

拷到新机器上第一次双击 `start.bat` 会慢一点，因为它要 `npm install` + 构建前端
（约 1 分钟）；之后就快了。
