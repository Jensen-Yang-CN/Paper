## 一、软件基本信息

| 项 | 内容 |
|---|---|
| 软件全称 | ClothInspect-Agent 服装智能质检系统 |
| 版本号 | V1.0 |
| 软件分类 | 人工智能应用软件 / 计算机视觉检测软件 |
| 开发语言 | Python 3.9、JavaScript（Vue 3） |
| 运行环境 | Windows 10/11，Python 3.9+，Node.js 18+（仅构建前端） |
| 开发框架 | FastAPI（后端）、Vue 3 + Vite + Vue Router（前端） |
| 核心算法库 | Ultralytics YOLOv11、PyTorch、OpenCV、Pillow |
| 外部服务 | 阿里云百炼 DashScope（qwen3-vl-plus 多模态大模型，兼容 OpenAI 协议） |
| 数据存储 | SQLite 3（单文件） |
| 软件定位 | 视觉检测模型与多模态大模型协同推理的服装表面微痕（破洞/污渍/褶皱）智能质检系统 |

**软件用途**：面向服装与面料的表面微痕质检场景，输入质检图片，输出缺陷类别与位置，
并给出每个缺陷框的完整判定依据与推理轨迹，辅助人工复核。

## 二、软件功能模块

### 模块一：图片上传模块

| 项 | 内容 |
|---|---|
| 功能描述 | 接收用户上传的服装质检图片，支持拖拽上传、格式与大小校验；提供内置样例图库，新用户无需准备数据即可体验完整流程 |
| 支持格式 | JPG / JPEG / PNG / BMP / WEBP，单张上限 20 MB |
| 实现位置 | `backend/app/api/detect.py`（`/api/detect/upload`、`/api/detect/sample`）<br>`backend/app/api/system.py`（`/api/samples` 样例库）<br>`backend/app/storage.py`（落盘与 URL 生成） |
| 前端界面 | `frontend/src/views/DetectView.vue`（拖拽区 + 样例网格） |
| 截图 | `02_检测工作台_样例库.png` |

**技术要点**：上传文件先写入临时文件再解码，避免中文文件名与特殊格式解析失败；
样例图库在服务启动时按"覆盖三类缺陷 + 含无缺陷负样本"的策略挑选并缓存，
每张样例附带真实标注作为参考答案。

### 模块二：YOLO 缺陷检测模块

| 项 | 内容 |
|---|---|
| 功能描述 | 调用冻结权重的 YOLOv11 模型对整图做前向推理，输出候选缺陷框的类别、像素坐标、归一化坐标、置信度与面积占比 |
| 缺陷类别 | hole（破洞）、stain（污渍）、wrinkle（褶皱） |
| 实现位置 | `backend/app/core/detector.py` |
| 接口 | `POST /api/detect/upload`、`POST /api/detect/sample` |
| 截图 | `03_检测工作台_协同结果.png` |

**技术要点**：
* 单例 + 线程锁：模型仅加载一次，避免并发请求重复占用显存；
* 延迟加载 + 预热：服务启动时完成 CUDA 初始化，首次请求不额外等待；
* 支持 GPU / CPU 切换（`.env` 中 `YOLO_DEVICE`）；
* 为避免与后续"置信度路由"循环论证，论文中的难度判据使用标注客观属性与类别，
  不使用模型置信度（软件中同样只把置信度用于路由，不用于难度定义）。

### 模块三：局部区域处理模块

| 项 | 内容 |
|---|---|
| 功能描述 | 以检测框为中心外扩 30% 裁出局部区域；区域过小时自动放大到最小边长；生成"尺度提示"文本，告知大模型该裁剪图在原图中的尺寸与占比；可选 CLAHE 对比度增强与锐化 |
| 实现位置 | `backend/app/core/cropper.py` |
| 参数 | `CROP_MARGIN=0.30`、`MIN_CROP=96` |
| 截图 | `03_检测工作台_协同结果.png`（"送给多模态大模型的局部视觉证据"区域） |

**技术要点**：局部裁剪是论文假设 H2 的核心。同一批 810 个检测框的对照实验表明，
大模型看裁剪图比看整图的判定准确率更高（0.643 vs 0.598），提升主要来自"拒绝假缺陷"。

### 模块四：多模态复核模块

| 项 | 内容 |
|---|---|
| 功能描述 | 将局部裁剪图与尺度提示送入多模态大模型，返回结构化 JSON 结论：是否为瑕疵、类别、置信度、判断理由 |
| 模型 | qwen3-vl-plus（DashScope 兼容 OpenAI 协议） |
| 实现位置 | `backend/app/core/vlm_client.py` |
| 输出结构 | `{"is_defect": bool, "category": "hole\|stain\|wrinkle\|none", "confidence": float, "reason": str}` |
| 截图 | `03_检测工作台_协同结果.png` |

**技术要点**：
* **双后端设计**：`QwenVLClient`（真实调用）与 `HeuristicVerifier`（离线启发式兜底）。
  未配置 API 密钥时自动降级，保证软件在无网络环境下仍可完整演示，
  界面上以醒目黄色提示标注"离线启发式复核，不代表论文结论"；
* **稳健解析**：容忍模型输出被 ```json 包裹或带前后缀说明的情况，并修正尾随逗号；
* **类别归一化**：兼容中英文类别表述。

### 模块五：Agent 协同决策模块

| 项 | 内容 |
|---|---|
| 功能描述 | 系统的核心机制。由检测置信度驱动的动态路由决定哪些疑难样本需要调用大模型，并按规则完成结果融合 |
| 实现位置 | `backend/app/core/router.py`（路由）<br>`backend/app/core/fusion.py`（融合）<br>`backend/app/core/agent_tools.py`（工具注册表）<br>`backend/app/core/pipeline.py`（流水线编排） |
| 路由规则 | `C_yolo ≥ T` → 直接接受 YOLO 判定；`C_yolo < T` → 转大模型复核 |
| 融合规则 | 大模型判为瑕疵 → 保留该框，且**类别以大模型为准**（类别纠错）；<br>判为非瑕疵 → 剔除该框（剔除误检）；<br>调用失败 → 按兜底策略保留 YOLO 原判；<br>**框的精确位置始终沿用 YOLO** |
| 默认阈值 | T = 0.60（Pareto 膝点，可由界面滑块在 0.30~0.90 间调整） |
| 截图 | `03_检测工作台_协同结果.png`（Agent 推理轨迹） |

**Agent 工具集**（Function Calling 风格声明，`GET /api/tools` 可导出）：

| 工具名 | 中文名 | 功能 |
|---|---|---|
| `detect_defect` | 视觉检测 | YOLOv11 输出候选缺陷框 |
| `route_decision` | 置信度路由 | 判定直接接受或转复核 |
| `crop_region` | 局部裁剪 | 外扩裁剪 + 放大 + 尺度提示 |
| `verify_with_vlm` | 多模态复核 | 大模型语义判定 |
| `enhance_region` | 区域增强 | CLAHE 对比度增强（可选） |
| `fuse_results` | 结果融合 | 规则融合与最终判定 |

**推理轨迹**：每一次工具调用都会记录工具名、显式参数、执行结论、耗时与结构化细节，
前端渲染为可展开的时间线，实现检测过程**全程可解释、可追溯**。

### 模块六：结果展示模块

| 项 | 内容 |
|---|---|
| 功能描述 | 检测框可视化、逐框决策溯源、仅 YOLO 与协同结果对比、检测报告导出 |
| 实现位置 | `backend/app/report.py`（报告图合成）<br>`frontend/src/components/BoxOverlay.vue`（检测框覆盖层）<br>`frontend/src/components/ResultDetail.vue`（结果详情）<br>`frontend/src/components/TraceTimeline.vue`（推理轨迹） |
| 截图 | `03_检测工作台_协同结果.png`、`04_检测工作台_仅YOLO对照.png`、`11_导出检测报告.png` |

**界面能力**：
* 检测框按类别着色并标注中文类别与置信度；支持按类别筛选、显示/隐藏标签、
  悬停高亮与点击定位（列表与图上框双向联动）；
* 一键切换 `协同结果 / 仅 YOLO 基线` 显示模式，直观对比两种模式的检出差异；
* **对比卡片**：并排展示"仅 YOLO 基线"与"协同推理"的检出框数、大模型调用次数，
  并逐条列出协同带来的变化（剔除误检 N 个 / 类别纠错 N 个 / 复核后保留 N 个）；
* **逐框明细表**：每个框的最终类别、置信度、路由去向、复核结论与判断理由；
* **报告导出**：合成带检测框、逐框标签与汇总信息的 PNG 报告图（含离线模式警示）。

### 模块七：检测记录模块

| 项 | 内容 |
|---|---|
| 功能描述 | 检测结果持久化存储、历史检索、统计总览与记录管理 |
| 实现位置 | `backend/app/db.py`、`backend/app/api/history.py` |
| 存储 | SQLite 单文件 `backend/data/clothinspect.db` |
| 接口 | `GET /api/history`、`GET /api/history/{id}`、`GET /api/history/statistics`、`DELETE /api/history/{id}`、`DELETE /api/history` |
| 截图 | `05_检测记录.png` |

**记录字段**：检测时间、源文件名、原图路径、图像尺寸、路由阈值、推理阈值、
复核模式与模型、候选框数、最终框数、大模型调用次数、剔除数、纠错数、
类别分布、总耗时、完整结果 JSON（含检测框与推理轨迹）。

**界面能力**：统计总览卡片（记录总数 / 累计缺陷框 / 累计大模型调用 / 平均耗时 / 类别分布）、
关键词检索、分页浏览、点击记录就地展开完整结果（原图 + 检测框 + 全部明细）、单条删除与全部清空。

## 五、技术特点

1. **推理时协同，模型零改动**：YOLOv11 权重完全冻结，协同能力全部由系统层实现，
   不需重新训练即可部署到已有检测模型之上。
2. **成本可控**：通过置信度路由把大模型调用量降到 0.75 次/图（全量复核为 2.7 次/图），
   在拿到全复核约 35% 性能提升的同时显著降低推理开销。
3. **全过程可解释**：推理轨迹完整记录每一步工具调用，逐框给出判定理由与类别纠错依据。
4. **离线可运行**：未配置大模型密钥时自动降级为离线启发式复核并明确标注，
   保证演示与答辩不受网络与密钥条件限制。
5. **数据与论文同源**：系统展示的实验数据直接读取论文定版结果文件，
   界面数字与论文数字不会漂移。
6. **开箱即用**：一键启动脚本自动完成环境探测、依赖检查、前端构建与服务启动。

## 六、使用限制与如实说明

1. 本软件为**方法验证与演示系统**，用于验证论文提出的协同推理机制，
   不追求企业级高可用部署（无复杂权限体系、无分布式部署）。
2. 系统界面中的单张图片检测结果为流程演示，**论文结论以重标 test 集 300 张
   上的批量实验为准**。
3. 未配置 `DASHSCOPE_API_KEY` 时使用的"离线启发式复核"**不是多模态大模型**，
   仅用经典图像统计量近似判断，相关结果不代表论文结论，界面上有明确标注。
4. 论文基线在修正后的重标 test 集上评估（mAP50 = 0.387、框级 F1 = 0.515）。
   早期 0.865 的口径因训练/验证集泄漏与旧标注漏标而虚高，不作为论文指标。
