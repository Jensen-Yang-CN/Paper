# ClothInspect-Agent 服装智能质检系统 V1.0

> **视觉模型与多模态大模型协同推理的服装表面微痕检测系统**
>
> 配套论文：《面向服装表面微痕检测的视觉模型与多模态大模型协同推理方法研究》

---

## 这个系统是做什么的

一句话：**让 YOLO 负责"快速发现"，让多模态大模型负责"疑难复核"，让协同路由机制负责"决定什么时候值得调用大模型"。**

它不是"用大模型替代 YOLO"，而是在**模型权重完全冻结**的前提下，在系统层加一个"裁判"：

```
输入服装质检图
      ↓
① YOLOv11 视觉检测（conf ≥ 0.25，输出候选框 + 置信度）
      ↓
② 置信度路由（阈值 T）        ← 本系统的核心机制
   ├─ 置信度 ≥ T  →  直接接受 YOLO 判定（不花钱调大模型）
   └─ 置信度 < T  →  判为疑难样本
                        ↓
③ 局部裁剪（外扩 30% + 过小放大 + 尺度提示）
                        ↓
④ 多模态大模型复核（qwen3-vl-plus）
   返回 {is_defect, category, confidence, reason}
                        ↓
⑤ 结果融合：VLM 判为瑕疵则保留该框、且类别以 VLM 为准（类别纠错）；
            判为非瑕疵则剔除该框；框的精确定位始终沿用 YOLO
      ↓
最终缺陷框 + 完整推理轨迹
```

**为什么这样设计**：YOLO 定位准但找不全（框级召回仅 0.475，褶皱只有 0.278）；
大模型判断强但定位粗。二者互补——用 YOLO 的精确框，用大模型的语义复核与类别纠错。

## 快速开始（3 分钟）

### 方式一：一键启动（推荐）

双击 **`start.bat`**（或右键 `start.ps1` → 使用 PowerShell 运行）。

脚本会自动完成：环境探测 → 依赖检查 → 前端构建（首次）→ 启动服务 → 打开浏览器。

### 方式二：手动启动

```powershell
# 1) 后端
cd backend
python run.py                # 默认 http://127.0.0.1:8000

# 2) 前端（若 frontend/dist 不存在，需先构建一次）
cd frontend
npm install --ignore-scripts
npm run build                # 产物由后端托管，访问 http://127.0.0.1:8000
```

打开 <http://127.0.0.1:8000> 即可使用；接口文档在 <http://127.0.0.1:8000/docs>。

### 方式三：前端开发模式（改界面时用）

```powershell
# 终端 1
cd backend ; python run.py
# 终端 2
cd frontend ; npm run dev     # 访问 http://localhost:5173，已配好 /api 代理
```

## 首次使用要做的两件事

系统**不配置任何东西也能跑通全流程**（会自动降级），但要做真实大模型复核需要两步：

### 1. 配置多模态大模型密钥（可选但推荐）

编辑项目根目录的 `.env`：

```ini
DASHSCOPE_API_KEY=sk-你的阿里云百炼密钥
VLM_MODE=auto
VLM_MODEL=qwen3-vl-plus
```

* **填了密钥** → 走真实 qwen3-vl-plus 复核，界面右上角显示 `✓ 真实 VLM 复核`
* **没填密钥** → 自动降级为**离线启发式复核**（用局部对比度 / 清晰度等统计量近似判断）。
  界面上会有醒目的黄色提示。**它不是大模型，仅用于保证离线也能演示完整流程，结果不代表论文结论。**

> 也可以把 `VLM_MODE` 设为 `heuristic` 强制离线（答辩彩排 / 演示无网络时用），
> 或设为 `real` 强制真实调用（无密钥时直接报错，便于排查配置问题）。

### 2. 确认模型权重

系统会自动在这些位置搜索 YOLOv11 权重：

1. `.env` 里的 `YOLO_WEIGHTS`
2. `../模型权重/Final_Model_V6_best.pt`（本项目所在的 Paper 目录下）
3. `backend/assets/weights/*.pt`

找不到时检测接口会返回 503 并给出明确提示。

### 检测工作台怎么用

1. **选图**：拖入自己的图片，或点下方内置样例（样例自带真实标注当"参考答案"，用来检验系统漏检/误检）
2. **调阈值 T**（不懂就用默认 0.6）：
   * `0.50` 低预算 · 约 0.48 次复核/张
   * **`0.60` 推荐（Pareto 膝点）· 约 0.75 次复核/张**
   * `0.70` 高精度 · 约 1.30 次复核/张
3. **点"开始检测"**，然后看右侧 **Agent 推理轨迹**——每个工具做了什么、耗时多少，都能展开看细节
4. **看对比卡片**：同一张图，`仅 YOLO 基线` vs `协同推理` 分别检出多少框、花了多少次大模型调用、剔除/纠错了什么
5. **切换显示模式**：图片上方的 `协同结果 / 仅 YOLO 基线` 开关可以直观对比两种模式的框

## Agent 工具集

论文第八节要求的最小工具集，全部已实现，接口 `GET /api/tools` 可直接导出 Function Calling 声明：

| 工具 | 中文名 | 作用 |
|---|---|---|
| `detect_defect` | 视觉检测 | YOLOv11 冻结模型输出候选缺陷框（类别 / 坐标 / 置信度） |
| `crop_region` | 局部裁剪 | 以框为中心外扩 30% 裁出局部区域、过小放大、生成尺度提示 |
| `verify_with_vlm` | 多模态复核 | qwen3-vl-plus 判定是否为瑕疵、属于哪一类 |
| `enhance_region` | 区域增强 | CLAHE 对比度增强 + 轻微锐化（可选步骤，默认关闭） |

执行顺序：`detect_defect → route_decision → crop_region → verify_with_vlm → fuse_results`。
每一次调用都会生成一条 **推理轨迹**（工具名、参数、结论、耗时），前端据此渲染时间线。

## 论文实验数据（系统与论文同源）

系统"实验结果"页直接读取 `backend/assets/paper/` 下的定版实验文件，
**界面上的数字与论文里的数字来自同一份数据源，不会漂移**。

核心结果（重标 test 集 300 张，模型 V6 冻结，框级 IoU = 0.5，类别严格口径）：

| 方法 | Precision | Recall | F1（严格） | 图像级 F1 | VLM 调用 / 张 |
|---|---:|---:|---:|---:|---:|
| YOLOv11 基线（conf=0.4） | 0.563 | 0.475 | 0.515 | 0.908 | 0 |
| 低阈值控制组（conf=0.25） | 0.553 | 0.528 | 0.540 | 0.907 | 0 |
| YOLO + 裁剪 + VLM（全复核） | 0.815 | 0.703 | **0.755** | 0.954 | 2.70 |
| **Ours 动态路由 T=0.60（推荐）** | **0.627** | **0.572** | **0.599** | 0.923 | **0.75** |
| Ours 动态路由 T=0.70 | 0.660 | 0.590 | 0.623 | 0.924 | 1.30 |

**结论**：协同方法 F1 `0.515 → 0.599`，且优于低阈值控制组（0.540）——
证明提升来自**大模型语义复核**，而不是单纯把 YOLO 阈值调低。

### 必须如实说明的边界

1. **全复核（F1 0.755）仍是性能上限**。动态路由的价值是**在预算内逼近上限**，
   不能写成"超过全复核"。T=0.6 用全复核 28% 的调用量拿到其 35% 的 F1 提升。
2. **面积/对比度定义的 Hard Set 与类别混淆**，"简单集"召回反而更低
   （0.396 < 0.531）。本数据集**有效难度轴是类别**：褶皱最难（基线召回仅 0.278），
   协同在褶皱上提升最大（0.278 → 0.417，相对约 +50%）。
3. **系统里单张图片的结果只是流程演示**，论文结论以重标 test 集 300 张的批量实验为准。

### 方法保真度验证（已实测）

系统自带的流水线在**全量 300 张 test 图**上复算，与论文定版值一致
（论文表中保留三位小数）：

| 指标 | 系统复算（全量 300，关闭复核） | 论文定版 | 一致性 |
|---|---:|---:|---|
| 仅 YOLO 基线 P / R / F1(严格) | 0.5628 / 0.4747 / **0.5150** | 0.563 / 0.475 / **0.515** | ✅ 一致 |
| 低阈值控制组 P / R / F1(严格) | 0.5531 / 0.5277 / **0.5401** | 0.553 / 0.528 / **0.540** | ✅ 一致 |
| 仅 YOLO 基线 F1(类别无关) | 0.7872 | 0.787 | ✅ 一致 |

复现命令（零 API 消耗）：

```powershell
cd backend
python scripts/validate_subset.py --n 300 --no-vlm
```

**真实大模型复核**（qwen3-vl-plus）在抽检子集上的表现——注意"协同 > 低阈值控制组"
这一论文核心结论被复现：

| 随机 90 张 test 图（种子 20260922） | F1（严格） | 相对基线 |
|---|---:|---:|
| 仅 YOLO 基线（conf=0.4） | 0.6227 | — |
| 降低推理阈值至 0.25（**不调大模型**） | 0.6348 | +0.012 |
| 协同推理（阈值 0.25 **+ 真实 VLM 复核**） | **0.6649** | **+0.042** |

即：单纯降低阈值只带来 +0.012，而**加上大模型语义复核后提升到 +0.042** ——
提升确实来自复核，而非降阈值。子集绝对指标高于全量（子集恰好偏易，关闭复核后
基线同样为 0.6227，已排除实现差异），故仅用于验证方法方向与量级的一致性。

> **延迟如实说明**：本次实测 qwen3-vl-plus 单次复核约 **2.3~2.6 s**，
> 高于论文记录的 1.8~2.0 s（网络状况与模型版本差异所致）；
> YOLOv11 单图推理约 20~100 ms，与论文一致。

## 常见问题

**Q：界面右上角一直显示"离线启发式复核"？**
A：没有读到 `DASHSCOPE_API_KEY`。检查项目根目录 `.env` 是否填写，然后重启后端。
启动日志会打印实际生效的复核后端。

**Q：检测接口返回 503 / "未找到 YOLOv11 权重"？**
A：把 `Final_Model_V6_best.pt` 放到 `backend/assets/weights/`，
或在 `.env` 中设置 `YOLO_WEIGHTS=<完整路径>`。

**Q：没有 GPU 能跑吗？**
A：能。在 `.env` 中设置 `YOLO_DEVICE=cpu`，单图推理会慢一些（约几百毫秒）。

**Q：想验证后端核心链路但不想开服务？**
A：

```powershell
cd backend
python scripts/smoke_test.py --list-samples        # 列出内置样例
python scripts/smoke_test.py --sample v00166.jpg   # 跑一遍完整协同推理并打印轨迹
```

**Q：怎么确认"系统里跑的"和"论文里写的"是同一套方法？**
A：项目自带保真度抽检脚本，用系统自己的流水线在 test 集子集上复算框级指标，
与论文定版值对比：

```powershell
cd backend
python scripts/validate_subset.py --n 80 --threshold 0.6   # 真实大模型复核
python scripts/validate_subset.py --n 80 --no-vlm          # 关掉复核做对照
```

论文定版参考值（全量 300 张，T=0.6）：仅 YOLO 基线 F1(严格) = 0.515，
协同推理 F1(严格) = 0.599，大模型调用 0.75 次/张。
抽检子集样本量小、指标会有波动，仅用于验证方法一致性；结果 JSON 存到
`backend/data/validate_subset_*.json`。

**Q：检测记录存在哪里？**
A：SQLite 单文件 `backend/data/clothinspect.db`；上传图、局部裁剪图、报告分别在
`backend/data/uploads|crops|reports/`。删除这些目录即可重置。

**Q：前端改了代码后页面没变？**
A：`frontend/dist` 是构建产物。跑 `cd frontend ; npm run build` 重新构建，
或使用 `npm run dev` 开发模式（带热更新）。
